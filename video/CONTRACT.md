# Home SOC walkthrough video — production contract

Goal: a ~7 minute narrated screen-walkthrough MP4 explaining what Home SOC is, its architecture, how it works, and how to
use it — with a highlighted animated mouse cursor clicking through the real dashboard.

Everything is produced by scripts in `video/` so the video can be regenerated after the product changes.
**Nothing in `video/` may modify the user's real data**: the demo runs against its own database in `video/demo_data/`.

Tools available and verified on this machine: Python 3.14, Pillow 12.3, numpy 2.5, ffmpeg 9.0 (full build, on PATH),
Playwright driving the **installed** Chrome (`p.chromium.launch(channel="chrome")` — the bundled browser download is blocked),
`edge_tts` 7.2.8 for neural narration (needs internet; voice `en-US-AndrewMultilingualNeural`, warm and clear).

## 0. Repo layout (every file)

```
video/
  CONTRACT.md            this file
  seed_demo.py           builds video/demo_data/homesoc.db — a fictional but realistic home network
  script.py              SCENES: the narration + action script (data only, no logic)
  narrate.py             edge-tts -> video/build/audio/scene_NN.mp3 (+ durations, + SRT)
  capture.py             Playwright -> video/build/shots/*.png (page states, scroll states, slides)
  slides.py              HTML for title cards and the architecture diagram (rendered by capture.py)
  compose.py             frames = shot + cursor + ripple + captions -> piped to ffmpeg per scene
  render.py              orchestrator: seed -> narrate -> capture -> compose -> concat -> mux -> out
  assets/cursor.png      generated by compose.py if missing (do not commit a binary)
  build/                 gitignored intermediates (audio/, shots/, clips/, frames/)
  out/HomeSOC-walkthrough.mp4    the deliverable (+ .srt sidecar)
```

Add `video/build/` and `video/demo_data/` to `.gitignore`. Keep `video/out/` committed-able but do not commit it now.

## 1. Demo data (`seed_demo.py`)

`python video/seed_demo.py [--force]` creates `video/demo_data/homesoc.db` using `homesoc.db.init_schema`, then inserts a
believable household. It must never touch the real `data/` directory. Use the real table columns (read `homesoc/db.py`).

Devices (18, plausible vendors and MACs from real OUI prefixes, hostnames a family would recognise):
gateway `192.168.1.1` (ISP router, lighttpd + Unbound), a Windows laptop (the host itself), two MacBooks, three iPhones,
an Android tablet, a smart TV, two Sonos speakers, an Epson printer, a Ring doorbell, two ESP32 smart plugs, a Nintendo
Switch, an Echo Dot, and **one deliberately interesting device**: an unbranded IP camera at `192.168.1.142` with Telnet
(23), RTSP (554) and an unauthenticated HTTP admin page (80).

Findings — a realistic mix that tells a story, roughly 30-40 rows across the lifecycle so the summary page has something to
show. Use only finding IDs that exist in `homesoc/findings/catalog.py` (grep it; do not invent):
- 2 critical: Telnet open on the camera (`NET-SVC-001`), and a KEV-confirmed vulnerability on the gateway (`NET-VUL-001`).
- 4-6 high: an outdated high-risk app, a WAN port open, a high-EPSS CVE, SMBv1 or similar.
- ~10 medium, ~10 low, a few info.
- **8-12 already resolved**, spread over the last 30 days, with `finding_events` rows so `how` is a believable mix of
  `auto_resolved` ("verified by rescan") and manual `resolved`. Vary `first_seen` -> `resolved_at` so the median
  time-to-remediate is a sensible number (hours to a few days), and so the summary's remediation rate lands near 25-35%.
- 1-2 acknowledged and 1 suppressed, so those states render.
Also seed: services for each device, a handful of `vulns` rows (real CVE ids for the gateway software), `host_checks`
covering pass/fail/needs_admin, `software` rows for the updates panel, 30 days of hourly `score` metrics that trend
**upward** (so the trend chart shows improvement), `dns_queries` + `dns_hourly` for the last 24 h with a believable
block rate (~30%) and recognisable blocked domains, `feeds` rows all healthy, `scans` and `jobs` history, and `events`.
Seeded timestamps must be relative to now so the video never looks stale.

The demo host must be named neutrally (`HOME-PC`), the SSID `Home-WiFi`, the public IP a documentation range address
(`203.0.113.42`, RFC 5737). No real MAC from the author's network, no real hostname, no real public IP.

## 2. Scene script (`script.py`)

```python
SCENES: list[Scene]          # ~14 scenes, total narration 6.5-8 minutes
@dataclass(frozen=True)
class Scene:
    id: str                  # "01-cold-open"
    narration: str           # what the voice says; plain prose, no stage directions
    shot: Shot               # what is on screen
    actions: list[Action]    # cursor choreography, timed as fractions of the scene duration
    caption: str | None      # optional lower-third label, e.g. "Overview"
```
```python
Shot  = Slide(html_fn="title") | Page(path="/", scroll=0) | PageSequence([...])
Action = Move(to="css=selector"|"xy=(x,y)", at=0.15)      # glide the cursor there, easing in/out
       | Click(at=0.35, then_shot=Page(...))              # ripple + crossfade to the resulting state
       | Scroll(to_y=800, at=0.5, seconds=1.2)            # smooth scroll of the captured page
       | Highlight(sel="css=...", at=0.4, seconds=2.0)    # soft glow rect around an element
       | Zoom(to_rect=(x,y,w,h), at=0.5, seconds=1.5)     # slow push-in, Ken Burns
```
Timings are fractions (0..1) of that scene's measured narration duration, so the visuals follow the voice automatically.

Narration voice and tone: second person, calm and concrete, no hype, no "in today's world". Explain *why* before *what*.
Never claim a capability the product does not have (it is not an antivirus engine and not an EDR — say so out loud in the
architecture scene). Numbers spoken must match what is on screen in the demo database.

Scene plan (adjust wording freely, keep the arc):
1. Cold open + title — the question the product answers.
2. What it is, in one breath — one process, your PC, nothing leaves the machine. What it is *not*.
3. Architecture — the animated diagram slide, narrated as data flowing: definitions in, scanners out, findings engine,
   dashboard, DNS resolver, scheduler.
4. Getting it running — the run.bat slide, what the first run does, then the dashboard appears.
5. Overview — score, "fix these first", severity mix, device count, DNS card, feed freshness, jobs.
6. Findings — filter to critical, open the Telnet-on-a-camera finding, read the remediation steps, acknowledge it.
7. Devices — inventory, open the camera's device page, its services, why an unknown device matters.
8. Vulnerabilities — KEV vs "theoretically vulnerable", EPSS, the gateway CVE.
9. Host posture and antivirus — Defender panel, what it verifies rather than replaces, needs-admin honesty, updates.
10. DNS filter — the query log, a blocked ad domain and a blocked malicious domain, overrides, the block rate.
11. Activity feed — one timeline of everything, filters, RSS.
12. Summary — found vs remediated, time to fix, the open worklist, export.
13. Using it day to day — the scheduler, notifications, the monthly routine, the CLI.
14. Close — where it runs, what it costs (nothing), the docs, MIT, and the safety line: only scan networks you own.

## 3. Narration (`narrate.py`)

`python video/narrate.py` writes `build/audio/scene_NN.mp3` for every scene with edge-tts
(`--voice en-US-AndrewMultilingualNeural --rate -4%`), measures each with ffprobe, and writes
`build/timings.json` = `{scene_id: {"audio": path, "seconds": float}}` plus `out/HomeSOC-walkthrough.srt`
(one cue per sentence, timed by proportional character length within the scene).
Cache by a hash of (text, voice, rate) so re-runs are free. Fail loudly with a clear message if the network is unavailable.

## 4. Capture (`capture.py`)

`python video/capture.py` starts `python -m homesoc serve --port 8899` with `HOMESOC_DATA=video/demo_data`
(as a subprocess it owns and always terminates, even on error), waits for readiness, then with Playwright + installed
Chrome, viewport **1600x900**, `device_scale_factor=2` (crisp text), `prefers-color-scheme: dark`:
- renders every slide from `slides.py` to `build/shots/slide_<name>.png`,
- for every Page shot, navigates, waits for network idle and for charts to have rendered, hides the auto-refresh
  timestamp jitter (inject CSS to freeze `.updated`), scrolls to the requested offset and screenshots to
  `build/shots/<scene>_<n>.png`,
- resolves every CSS selector used by an Action into pixel coordinates (in the 1600x900 CSS space) and writes
  `build/geometry.json` = `{scene_id: {selector: [x, y, w, h]}}` so the compositor knows where to put the cursor,
- for a `Click` with `then_shot`, performs the real click and captures the resulting state as the "after" image.
Screenshots are full-viewport (not full-page); long pages are handled with explicit scroll states.
If a selector does not resolve, fail with the scene id and selector name — never silently place the cursor at 0,0.

## 5. Compositing and render (`compose.py`, `render.py`)

Output: **1920x1080, 30 fps, H.264 yuv420p, CRF 19, AAC 192k**, faststart. Frames are generated in memory and piped to
ffmpeg via stdin as raw `rgb24` (`-f rawvideo -pix_fmt rgb24 -s 1920x1080 -r 30 -i -`). Never write 10,000 PNGs to disk.

Each 1600x900 (at 2x = 3200x1800) shot is letterboxed onto the 1920x1080 canvas with a subtle dark background
(`#0b0f14`) and a 12 px rounded border with a soft shadow, so the dashboard looks like a window, not a flat screenshot.

The cursor: a crisp white arrow with a thin dark outline and a drop shadow, drawn programmatically (no external asset),
sitting inside a soft translucent accent-coloured halo (~34 px radius) so it is always findable. Movement uses
ease-in-out cubic between waypoints, never linear, and never teleports. A `Click` plays a ripple: two expanding rings
that fade over 450 ms, plus a 60 ms cursor "press" scale-down, and the crossfade to the after-state begins 120 ms after
the ripple so the cause-and-effect reads correctly.

`Highlight` draws a rounded rect glow around the element and dims the rest of the frame slightly (a 25% dark scrim) so
the eye goes to the right place. `Zoom` is a slow ease-in-out push toward a rect, never more than 1.6x.
Captions: a lower-third pill, bottom-left, 34 px semibold, fading in/out over 300 ms.
Scene transitions: 400 ms cross-dissolve. Slides may use a gentle 1.03x drift.

`render.py` runs the whole pipeline end to end, prints a per-scene progress line with the elapsed time, concatenates the
per-scene clips with the concat demuxer, muxes the narration track, and writes `out/HomeSOC-walkthrough.mp4` plus the
`.srt`. It must be idempotent and support `--only <scene-id>` for iterating on one scene and `--no-capture` to reuse
existing shots. Total render should stay under ~10 minutes.

## 6. Quality bar

- Every number spoken matches what is visible on screen at that moment.
- The cursor is over the element before the click ripple fires, and the page state changes after it.
- No scene shows the author's real network data, real MAC addresses, real SSID or real public IP.
- Text is legible: the dashboard is captured at 2x and downscaled once, never upscaled.
- Audio starts ~0.3 s after the visual settles at each scene start, and there is 0.6 s of room tone at the very end.
- The finished file plays in Windows Media Player / VLC / a browser, and `ffprobe` reports one H.264 video stream and one
  AAC audio stream of the same duration (within 0.5 s).
